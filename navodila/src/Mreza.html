Dom Obroki – omrežje, dostop in strežnik

Navodila za skrbnika omrežja · dopolnilo k Kakoinstaliram.pdf

1. Pregled možnosti

Kdo naj dostopaRešitevPoglavje

Oblačna različica je že dosegljiva z interneta (HTTPS, varnostne kopije baze in posodobitve urejamo mi). Lokalno namestitev potrebujete le, če želite, da podatki ostanejo na vaši strojni opremi ali v vašem omrežju.

Nastavitve so v datoteki local/nastavitve.env v mapi aplikacije. Po vsaki spremembi aplikacijo znova zaženite (Windows: ponovno zaženite zazeni.bat ali opravilo »Dom Obroki«; Linux: sudo systemctl restart dom-obroki).

2. Samo na tem računalniku

HOST=127.0.0.1
PORT=8080

Aplikacija sprejema le povezave z istega računalnika (http://localhost:8080). Drugi računalniki je ne vidijo, tudi če požarni zid ni nastavljen. To je tudi pravilna nastavitev, ko pred aplikacijo stoji Caddy (poglavji 5 in 6).

3. Samo v lokalnem omrežju in v domeni

3.1 Strežnik

  1. Računalnik/strežnik naj ima stalen IP naslov (statičen ali rezervacija v DHCP), npr. 192.168.10.20.
  2. V nastavitve.env: 
    HOST=0.0.0.0
PORT=8080
  3. Odprite vrata le za lokalno omrežje.

    Windows (PowerShell kot skrbnik) – LocalSubnet pomeni samo omrežje, v katerem je strežnik:

    New-NetFirewallRule -DisplayName "Dom Obroki" -Direction Inbound -Protocol TCP -LocalPort 8080 `
  -RemoteAddress LocalSubnet -Profile Domain,Private -Action Allow

    Če so v domu ločena omrežja (npr. žično za zaposlene in brezžično), namesto LocalSubnet naštejte omrežja: -RemoteAddress 192.168.10.0/24,192.168.20.0/24. Pravilo lahko za več strežnikov razdelite tudi s skupinskim pravilnikom (GPO → Windows Defender Firewall).

    Linux (ufw):

    sudo ufw allow from 192.168.10.0/24 to any port 8080 proto tcp
sudo ufw allow OpenSSH
sudo ufw enable
  4. Na usmerjevalniku/požarnem zidu proti internetu vrat 8080 ne preusmerjajte – tako aplikacija od zunaj ni dosegljiva.

3.2 Ime v domeni (DNS)

Da uporabnikom ni treba pomniti IP naslova, v DNS strežniku domene (Active Directory) dodajte zapis A, npr. obroki.dom.local:

  • DNS Manager → Forward Lookup Zones → vaša cona → desni klik New Host (A or AAAA) → ime obroki, IP strežnika; ali
  • PowerShell na domenskem krmilniku: 
    Add-DnsServerResourceRecordA -ZoneName "dom.local" -Name "obroki" -IPv4Address 192.168.10.20

Uporabniki odprejo http://obroki.dom.local:8080. Povezavo lahko vsem razdelite s skupinskim pravilnikom (bližnjica na namizju ali zaznamek brskalnika).

Naprave, ki niso v domeni (osebni telefoni na šolskem Wi-Fi, gostujoči računalniki), ime obroki.dom.local razrešijo le, če jim DHCP kot DNS strežnik dodeli domenski DNS. Sicer naj uporabijo IP naslov (http://192.168.10.20:8080) – ali pa dodajte omrežje Wi-Fi v pravilo požarnega zidu in DNS, oziroma tega omrežja namenoma ne dodajte, če naprave izven domene ne smejo dostopati.

3.3 Brez vrat v naslovu in s šifriranjem (priporočeno)

Na običajnem HTTP gredo gesla po omrežju nešifrirana. Bolje je, da pred aplikacijo postavite Caddy (poglavje 5) in ostane HOST=127.0.0.1. Za ime, ki obstaja samo v domeni (.local), Caddy uporabi lasten certifikat:

obroki.dom.local {
	tls internal
	reverse_proxy 127.0.0.1:8080
}

Korensko potrdilo Caddy (Linux: /var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt) razdelite računalnikom v domeni z GPO (Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities), sicer brskalnik opozarja. Če ima domena svoj CA (AD CS), lahko certifikat izda ta. V požarnem zidu nato namesto 8080 dovolite vrata 443 (in 80).

4. V domeni in tudi od zunaj

Za zaposlene, ki dostopajo tudi od doma, je najvarnejši VPN: aplikacija ostane nastavljena kot v poglavju 3 in ni vidna na internetu, uporabnik pa se od zunaj najprej poveže v omrežje doma.

  • Če dom že ima VPN (požarni zid z SSL VPN / IPsec, Windows RRAS ali Always On VPN), dodajte VPN omrežje v pravilo požarnega zidu iz 3.1 (npr. -RemoteAddress LocalSubnet,10.8.0.0/24) in DNS strežnik domene v nastavitve VPN.
  • Sicer je preprosta rešitev WireGuard na usmerjevalniku ali na strežniku (odprta so samo vrata UDP 51820, odjemalci za Windows, macOS, Android, iOS).

Če želite, da aplikacijo uporabljajo tudi dijaki s svojimi telefoni, VPN ni praktičen – aplikacijo objavite na internetu (poglavje 5 ali 6).

5. Objava na internetu (lastni strežnik)

5.1 Kaj potrebujete

  • Strežnik z Linuxom (priporočeno Ubuntu LTS) s stalnim delovanjem; aplikacija nameščena po Kakoinstaliram.pdf, poglavje 2.
  • Javni IP naslov: strežnik je neposredno na internetu, ali pa na usmerjevalniku/požarnem zidu doma preusmerite vrata TCP 80 in 443 na notranji IP strežnika (port forwarding / NAT).
  • Ime v DNS, npr. obroki.vas-dom.si: pri upravitelju vaše domene (pogosto Arnes ali ponudnik gostovanja) dodajte zapis A z javnim IPv4 (in AAAA z IPv6, če ga imate).

5.2 Caddy – samodejni HTTPS

Caddy sprejema povezave z interneta, sam pridobi in obnavlja brezplačen certifikat Let's Encrypt in jih posreduje aplikaciji. Aplikacija ostane na HOST=127.0.0.1, zato ni neposredno dosegljiva.

sudo apt install -y caddy
sudo cp /opt/dom-obroki/local/Caddyfile.primer /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile          # vpišite svoje ime namesto obroki.vas-dom.si
sudo systemctl reload caddy

Vsebina Caddyfile:

obroki.vas-dom.si {
	encode gzip
	reverse_proxy 127.0.0.1:8080
}

Po nekaj sekundah je aplikacija dosegljiva na https://obroki.vas-dom.si. Za pridobitev certifikata morata biti vrata 80 in 443 dosegljiva z interneta in DNS zapis mora že kazati na strežnik. Dnevnik: journalctl -u caddy -f. (Če paketa caddy v vaši distribuciji ni, sledite navodilom na caddyserver.com/docs/install.)

5.3 Požarni zid in utrditev strežnika

sudo ufw default deny incoming
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp   # SSH le iz notranjega omrežja / VPN
sudo ufw enable
sudo apt install -y unattended-upgrades fail2ban                # samodejne varnostne posodobitve, zaščita SSH
  • Vrata 8080 in 5432 (PostgreSQL) naj ne bodo odprta navzven.
  • SSH: prijava s ključi, onemogočena prijava z geslom in za root (PasswordAuthentication no, PermitRootLogin no v /etc/ssh/sshd_config).
  • Močna gesla za vse račune v aplikaciji; računi odšlih zaposlenih naj bodo zaklenjeni.
  • Dnevne varnostne kopije baze (Kakoinstaliram.pdf, poglavje 4) in njihova kopija izven strežnika.
  • Aplikacija hrani osebne podatke mladoletnih – obseg obdelave in hrambe uskladite s pooblaščeno osebo za varstvo osebnih podatkov.

5.4 Windows strežnik

Na Windows je postopek enak: Caddy prenesete s caddyserver.com/download (datoteka caddy.exe), Caddyfile postavite v isto mapo in ga zaženete kot opravilo ob zagonu (tako kot aplikacijo v Kakoinstaliram.pdf, korak 7, z argumentom run --config C:\Caddy\Caddyfile). V požarnem zidu odprite 80 in 443. Za javni strežnik priporočamo Linux.

6. Namestitev na Arnesov strežnik (»Strežnik po meri«)

Arnes članicam (šolam, domovom …) nudi storitev Strežnik po meri (SPM) – virtualni strežnik v Arnesovem podatkovnem centru z javnim IPv4 in IPv6 naslovom. Arnes zagotovi strojne vire in omrežje; namestitev, vzdrževanje, varnost in varnostne kopije so v pristojnosti vašega skrbnika. Pogoje uporabe preverite pri Arnesu.

6.1 Pridobitev dostopa

  1. Skrbnik potrebuje AAI račun (ArnesAAI) zavoda.
  2. Odgovorna oseba zavoda (ravnatelj) ali njen pooblaščenec se prijavi v Portal članic (portal.arnes.si) z AAI računom.
  3. Izbere Naročanje storitev → Strežnik po meri, v polju Članica izbere zavod, pod Dodaj pooblaščenca vpiše e-naslov skrbnika in klikne Pošlji vabilo.
  4. Skrbnik prejme e-pošto, se prijavi z AAI računom in klikne Potrdi povabilo.
  5. Zavodi, ki niso v federaciji ArnesAAI, izpolnijo prijavnico za Strežnik po meri (na spletni strani Arnesa) in jo pošljejo na helpdesk@arnes.si; skrbnik v tem primeru potrebuje gostujoči AAI račun.

Začetna kvota je 2 vCPU, 4 GB RAM, 40 GB diska in povezava 1 Gb/s (IPv4 in IPv6) – za Dom Obroki povsem dovolj. Več virov lahko zaprosite na helpdesk@arnes.si.

6.2 Ustvarjanje virtualnega strežnika

  1. Prijava v portal spm.arnes.si z AAI računom.
  2. Nov virtualni strežnik → izberite kvoto → predlogo z operacijskim sistemom (priporočamo aktualno Ubuntu LTS; če je ni, AlmaLinux/Rocky ali prazno predlogo z namestitvijo iz ISO) → paket virov in velikost diska.
  3. Določite uporabniško ime in geslo (oz. SSH ključ) za prijavo. Arnes jih ne more obnoviti – shranite jih na varno.
  4. Kliknite Ustvari. Strežnik dobi IPv4 naslov prek DHCP in ime oblike xxx.ablak.arnes.si (vidno v portalu).
  5. IPv6 nastavite ročno po navodilih Arnesa: prehod 2001:1470:8000:400::1, naslov se ujema s številko imena – npr. 555.ablak.arnes.si = 2001:1470:8000:400::555.

6.3 Namestitev aplikacije

  1. Prijavite se: ssh uporabnik@xxx.ablak.arnes.si (Windows: PowerShell ali PuTTY).
  2. Posodobite sistem: sudo apt update && sudo apt full-upgrade -y (Alma/Rocky: sudo dnf upgrade -y).
  3. Namestite Node.js, PostgreSQL, bazo in aplikacijo po Kakoinstaliram.pdf, poglavje 2 (datoteke prenesete na strežnik z scp ali WinSCP, ali z git clone). HOST=127.0.0.1 pustite.
  4. DNS: pri upravitelju domene zavoda dodajte zapis CNAME obroki.vas-dom.si → xxx.ablak.arnes.si (ali A/AAAA z IP naslovoma strežnika). Lahko pa uporabite kar ime xxx.ablak.arnes.si.
  5. Namestite Caddy in v Caddyfile vpišite izbrano ime (poglavje 5.2).
  6. Požarni zid in utrditev po poglavju 5.3 (Alma/Rocky: firewalld – sudo firewall-cmd --permanent --add-service=http --add-service=https && sudo firewall-cmd --reload). SSH omejite na IP naslove doma, če je mogoče.
  7. Varnostne kopije (Kakoinstaliram.pdf, poglavje 4) redno prenašajte z strežnika, npr. v Arnes Shrambo ali na disk v domu.
  8. Preizkus: https://obroki.vas-dom.si, prijava z administratorjem, ustvarjenim z npm run admin.

6.4 Arnesove varnostne smernice (povzetek)

  • redne posodobitve sistema; odstranite pakete, ki jih ne potrebujete,
  • močna gesla, onemogočena neposredna prijava root, prijava s SSH ključi,
  • požarni zid (ufw / firewalld), zaprta vsa vrata, ki jih ne uporabljate,
  • redne varnostne kopije na drugo lokacijo.
